# تشغيل ونشر نظام الامتحانات

## المتطلبات

- لا يحتاج الموقع إلى `npm` أو Node.js أو build أو أي تثبيت على جهازك.
- يحتاج إلى الإنترنت، ومشروع Supabase مفعّل لتسجيل الدخول وحفظ درجات الطلاب.
- الواجهة التي تُنشر هي `index.html`، وخلفيتها قاعدة Supabase.

## الإعداد الأول

1. استخدم جداول الامتحانات الموجودة (`exams_exams`, `exams_questions`, `exams_answer_keys`, `exams_attempts`) كما هي؛ لا تنشئ جداول بديلة.
2. افتح Supabase → **SQL Editor** وشغّل [دوال Supabase الآمنة](./exams-existing-schema-functions.sql). لا تنشئ هذه الدوال جداول، وتستخدم حساب الطالب لتقييد الوصول للمحاولة والإجابات.
3. من **Authentication → Providers** فعّل Google والبريد الإلكتروني/كلمة المرور، وأدخل بيانات OAuth الخاصة بتطبيق Google. في Google Cloud Console، أضف `https://exams.ilogia-eg.com` إلى **Authorized JavaScript origins**، واستخدم Client ID نفسه في الواجهة وفي إعداد Google داخل Supabase. يطلب زر Google رمز الهوية عبر Google Identity Services ثم يرسله إلى Supabase؛ لا يغادر المستخدم صفحة الموقع ولا تُرسل كلمة مرور Google إلى الموقع. أضف رابط الموقع أيضًا إلى **Authentication → URL Configuration → Redirect URLs** واضبط **Site URL** عليه لاستخدامات إعادة التوجيه الأخرى. عند أول دخول بـGoogle، ينشئ Supabase مستخدمًا جديدًا في `auth.users` تلقائيًا؛ لا يحتاج المستخدم إلى إنشاء حساب منفصل أو تأكيد البريد مرة أخرى. عمليات الدخول التالية تعود إلى الحساب نفسه. التسجيل بالبريد يرسل الاسم في `user_metadata.full_name`.
4. تأكد من وجود مشغّل `auth.users` ينشئ صفًا في `profiles` لكل مستخدم جديد، سواء سجّل بالبريد أو Google، وينسخ بيانات الاسم والبريد والصورة من `user_metadata` عند توفرها. يعتمد تحميل بيانات الملف الشخصي على هذا الصف؛ أما سجل الامتحانات فيرتبط مباشرة بمعرّف مستخدم Supabase.
5. انشر ملفات المشروع على GitHub Pages أو استضافة ملفات ثابتة. لا تشغّل أوامر بناء. إذا كنت تستخدم GitHub Pages، فعّل النشر من الفرع والمجلد الصحيحين في إعدادات المستودع.
6. للدومين `exams.ilogia-eg.com`، وجّه سجل DNS من نوع CNAME إلى نطاق GitHub Pages، مع الإبقاء على ملف `CNAME`.

## حفظ الدرجات

يستطيع الطالب إنشاء حساب أو تسجيل الدخول بالبريد وكلمة المرور أو Google. تسجيل Google يستخدم نافذة Google المضمّنة في تدفق الهوية (GIS) ويُكمل التحقق داخل الصفحة عبر Supabase Auth، دون تحويل الموقع إلى صفحة أخرى؛ لا يرسل الموقع كلمة مرور Google إليه. عند أول دخول، ينشئ Supabase حساب Auth تلقائيًا، ثم يحمّل الموقع بيانات `profiles` و`public_profiles` وسجل المحاولات المرتبطة بمعرّف الحساب. يلزم أن ينشئ مشغّل `auth.users` صف `profiles` للمستخدم الجديد. إذا كان الحساب موجودًا بالفعل في مشروع Supabase نفسه، يعود الدخول إلى الحساب وبياناته نفسيهما.

تُحفظ الإجابات بصيغة JSONB في `exams_attempts.answers`، وتحسب الإجابات الصحيحة من `exams_answer_keys` عند التسليم. تحفظ `exams_attempts.score` كعدد الإجابات الصحيحة، وترتبط المحاولة بمعرّف حساب الطالب في `user_id`. النسبة للعرض تحسب بقسمة الدرجة على عدد الأسئلة. لا تعتمد الدرجة على تخزين المتصفح.

## التأكد من التشغيل

1. افتح رابط الموقع وسجّل الدخول.
2. ابدأ اختبارًا، واختر إجابة، وانتقل بين الأسئلة. تظهر حالة الحفظ، ويمكنك الضغط على **إعادة حفظ الإجابات** إذا تعذر حفظ إجابة.
3. سلّم الاختبار وتأكد من ظهور النتيجة.
4. من Supabase **Table Editor**، راجع `exams_attempts` للتأكد من حفظ `score`, `finished_at`, `user_id` و`answers`.
